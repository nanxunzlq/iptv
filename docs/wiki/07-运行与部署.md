# 07 · 运行与部署

按"使用者的四种角色"组织：只播直播源、只校验数据、用探活工具、部署 iptv-api 生成源。每节给出可直接执行的命令。

---

## 一、使用现成直播源（零安装）

### 1.1 订阅地址

| 格式 | 地址 |
|---|---|
| M3U（推荐，含 EPG） | `https://raw.githubusercontent.com/nanxunzlq/iptv/main/%E6%B2%B3%E5%8D%97%E7%A7%BB%E5%8A%A8/%E6%B2%B3%E5%8D%97%E7%A7%BB%E5%8A%A8.m3u` |
| DIYP TXT | `https://raw.githubusercontent.com/nanxunzlq/iptv/main/%E6%B2%B3%E5%8D%97%E7%A7%BB%E5%8A%A8/%E6%B2%B3%E5%8D%97%E7%A7%BB%E5%8A%A8.txt` |

路径含中文，上表为 URL 编码后的形式。播放器不支持编码地址时，直接下载仓库内 [`河南移动/`](../../河南移动/) 的对应文件本地导入。

### 1.2 播放器配置

| 播放器 | 操作 |
|---|---|
| PotPlayer | 右键 → 打开 → 打开链接（填 m3u 地址） |
| TiviMate / IPTVnator | 新建播放列表 → 远程 URL → 填 m3u 地址 |
| DIYP / 影视类安卓应用 | 「直播配置 / 接口」填 txt 地址 |

### 1.3 网络前提

源为 `iptv.cdn.ha.chinamobile.com` 的**河南移动宽带内网源**。非该网络环境（含 GitHub Actions runner、境外 VPS、其他运营商）**无法播放**，这不是文件损坏。

## 二、本地校验数据一致性

不需要任何第三方库：

```bash
python .github/scripts/check_playlist_equivalence.py
```

校验内容：

- 两份文件频道名集合完全一致；
- URL 集合完全一致；
- 同名频道的 URL 必须相同（顺序允许不同）。

失败时退出码为 1，并打印缺失/多余的频道与 URL 差异。CI 中同一脚本的输出会写入 Step Summary。

## 三、使用 `iptv-checker`（链接探活）

### 3.1 前置

- Node.js **>= 22.12.0**
- FFmpeg（提供 `ffprobe`）

### 3.2 安装与运行

```bash
cd tools/iptv-checker
npm install

# 检查远程播放列表
npx iptv-checker https://example.com/playlist.m3u

# 检查本地文件
npx iptv-checker ./河南移动.m3u

# 管道输入
cat playlist.m3u | npx iptv-checker
```

### 3.3 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-o, --output <dir>` | `iptv-checker_<yyyymmddhhMMss>` | 输出目录 |
| `-t, --timeout <ms>` | `60000` | 单请求/ffprobe 超时 |
| `-p, --parallel <n>` | CPU 核数 | 并发批次大小 |
| `-d, --delay <ms>` | `0` | 请求间隔 |
| `-r, --retry <n>` | `0` | 失败重试次数 |
| `-a, --user-agent <s>` | `IPTVChecker/<ver>` | 自定义 UA |
| `-x, --proxy <url>` | 无 | HTTP 代理 |
| `-k, --insecure` | 关闭 | 跳过 TLS 校验 |
| `-D, --debug` | 关闭 | 调试输出 |

### 3.4 输出

```text
iptv-checker_20261023101500/
├── online.m3u     # 可用条目
└── failed.m3u     # 失败条目
```

终端输出 `Total / Online / Failed` 统计，退出码 0（执行成功）/ 1（异常）。

### 3.5 运营商源的关键注意事项

河南移动 CDN 对高频请求的反馈是**短暂 404**，而非拒连。默认并发会把正常源判成"间歇性失效"：

```bash
npx iptv-checker -p 1 -r 1 -t 8000 ./河南移动.m3u
```

- 并发建议 **1~2**，批次之间留间隔；
- 判失效前**冷却数分钟后复验**；
- 高并发得到的"失败列表"不能直接用于删除频道。

### 3.6 从源码跑测试

```bash
cd tools/iptv-checker
env -u http_proxy -u https_proxy npm test   # Windows PowerShell: 先 Remove-Item Env:http_proxy
```

期望 16 个用例全部通过。

## 四、部署 `iptv-api`（自动生成源）

### 4.1 初始化子模块

主仓库默认**不包含**子模块内容：

```bash
# 克隆时递归拉取
git clone --recurse-submodules --depth 1 https://github.com/nanxunzlq/iptv.git

# 已克隆后补充
git submodule update --init --depth 1 tools/iptv-api
```

### 4.2 准备输入

进入 `tools/iptv-api/`，按需编辑 `config/`：

| 文件 | 作用 | 必改 |
|---|---|---|
| `config.ini` | 主配置 | 按需 |
| `demo.txt` | 要生成哪些频道、分组顺序 | ✓（决定输出范围） |
| `subscribe.txt` | 订阅源 URL 列表 | 至少配一个源 |
| `local.txt` / `local/` | 本地源 | 可选 |
| `epg.txt` | EPG 源 | 可选 |
| `alias.txt` | 频道别名 | 可选 |

> 项目本身**不提供数据源**；没有配置任何源时运行会以 `completed_empty` 结束，`run_state.json` 的 `reason` 为 `no_source_configured`。

### 4.3 本地运行

```bash
cd tools/iptv-api
pip install pipenv
pipenv install --dev     # 服务部署可用 --deploy 跳过 GUI 依赖

pipenv run dev           # 执行更新（按 config.ini 的 update_mode 决定是否常驻）
pipenv run service       # 只启动 Web 结果服务
pipenv run ui            # 启动桌面 GUI（Windows / macOS）
pipenv run ui_build      # 打包当前平台安装包
```

运行产物见 [05 第 3 节](./05-数据模型与配置.md#三产物与落盘) 与项目内 `output/`。

### 4.4 Docker 部署

**Compose（推荐）**：

```bash
docker compose up -d
PORT=8088 docker compose up -d          # 改宿主机端口
```

**手动**：

```bash
docker pull guovern/iptv-api:latest
docker run -d -p 80:8080 \
  -v /iptv-api/config:/iptv-api/config \
  -v /iptv-api/output:/iptv-api/output \
  guovern/iptv-api
```

镜像内进程（[entrypoint.sh](../../tools/iptv-api/entrypoint.sh)）：

1. 把 `/iptv-api-config/*` 首次复制到挂载的 `config/`（不覆盖已有文件）；
2. 渲染 nginx 配置并后台启动（HTTP + RTMP）；
3. 后台启动 `main.py` 执行更新；
4. 前台以 gunicorn 运行 Flask（`127.0.0.1:5180`，单 worker）。

### 4.5 端口

| 端口 | 默认 | 用途 | 是否对外 |
|---|---|---|---|
| nginx HTTP | `8080` | 结果页/订阅/EPG/台标/推流 HLS | ✓ |
| Flask | `5180` | 内部 API，由 nginx 反代 | ✗ |
| nginx RTMP | `1935` | 推流入口 | 仅推流客户端 |
| 宿主机映射 | `80` | Compose 的 `${PORT}` | ✓ |

### 4.6 环境变量

| 变量 | 说明 | 默认 |
|---|---|---|
| `PUBLIC_URL` | 推荐：完整公网地址（生成播放列表/EPG/台标链接） | 空 |
| `PUBLIC_DOMAIN` | 兼容：`PUBLIC_URL` 为空时的域名/IP | `127.0.0.1` |
| `PUBLIC_PORT` | 兼容：宿主机映射端口 | `80` |
| `NGINX_HTTP_PORT` | 高级：容器内 HTTP 端口 | `8080` |
| `SERVICE_PORT` | 覆盖 nginx HTTP 端口 | 空 |
| `CDN_URL` | 订阅/EPG/台标加速 | 空 |
| `HTTP_PROXY` | 仅用于订阅与 EPG，测速直连 | 空 |
| 任意配置键 | `key` / `KEY` / `SECTION_key` / `SECTION_KEY` 四种写法均可 | — |

### 4.7 Web 接口

| 路径 | 内容 |
|---|---|
| `/` | 结果首页（预览 + 下载） |
| `/m3u`、`/txt` | 全量结果 |
| `/ipv4`、`/ipv6` 及 `/ipv4/m3u`、`/ipv6/txt` 等 | 分协议结果 |
| `/hls` 及 `/hls/m3u`、`/hls/txt`、`/hls/ipv4`… | RTMP 推流结果 |
| `/epg/epg.xml`、`/epg/epg.gz` | 节目单 |
| `/log/result`、`/log/speed-test`、`/log/statistic`、`/log/unmatch` | 日志页 |
| `/logo/<file>` | 台标 |
| `/hls_proxy/<channel_id>` | HLS 代理（解决跨域/防盗链） |

## 五、GitHub Actions

### 5.1 主仓库自检

[`iptv-health-check.yml`](../../.github/workflows/iptv-health-check.yml)：

| 触发 | 说明 |
|---|---|
| `schedule` | 每周一 03:17 UTC |
| `push` | 修改 `河南移动/**`、`README.md`、workflow 或脚本时 |
| `workflow_dispatch` | 手动；可勾选 `probe_streams` 实测源 |

- 默认只做**文件一致性**校验（频道数、结构、分组质量、等价性、订阅地址 HTTP 200）；
- `probe_streams=true` 才实测运营商源——CI 环境通常不可达，结果仅作参考；
- 失败会创建/更新唯一一条 `[自动巡检]` Issue，不产生提交。

### 5.2 子模块的生成工作流

`tools/iptv-api/.github/workflows/main.yml`（`Generate playlist manually`）为**纯手动**触发：

- 用 Python 3.14 + Pipenv 安装依赖后执行 `pipenv run dev`；
- 结果通过 Pages Artifact + 本次运行独立的预发布 Release 发布；
- **不提交回 Git**，旧的 `raw.githubusercontent.com/.../output/...` 链接不再更新；
- 需要定时生成请用 Docker / 命令行 / GUI。

前置：Fork 后在 `Settings → Pages` 把发布源设为 `GitHub Actions`，再手动运行该 workflow。播放入口：

```text
https://<用户名>.github.io/<仓库名>/result.m3u
https://<用户名>.github.io/<仓库名>/result.txt
```

## 六、运行形态对照

| 形态 | 入口 | 常驻 | 服务 | 适用 |
|---|---|---|---|---|
| 订阅现成源 | 播放器 | 否 | 无 | 普通观看 |
| 本地校验 | `check_playlist_equivalence.py` | 否 | 无 | 改数据后 |
| 探活 | `iptv-checker` | 否 | 无 | 采集后复核 |
| CLI 更新 | `pipenv run dev` | 视 `update_mode` | 可选 | 服务器/定时任务 |
| Web 服务 | `pipenv run service` | 是 | Flask + nginx | 已有结果、只对外提供 |
| 桌面 GUI | `pipenv run ui` | 是 | 内嵌服务 | Windows / macOS 个人使用 |
| Docker | `docker compose up -d` | 是 | nginx + Flask + RTMP | NAS / 服务器 |
| GitHub Actions | 手动 workflow | 否 | Pages | 低频、免运维 |

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 所有频道无法播放 | 不在河南移动宽带网络 | 换网络；或仅作格式参考 |
| 订阅地址返回 404 | 分支名/路径编码错误 | 使用第一节的完整编码 URL；或下载文件导入 |
| 高频探活大面积 failed | CDN 对高频请求返回临时 404 | 降到 `-p 1`，冷却数分钟后复验 |
| `Executable "ffprobe" not found` | 未安装 FFmpeg 或不在 PATH | 安装 FFmpeg 并重启终端 |
| iptv-api 输出为空（`completed_empty`） | 未配置任何源，或模板为空 | 检查 `demo.txt`、`subscribe.txt`、`open_local/open_subscribe` |
| GUI 无法获取分辨率 | 未安装 FFmpeg | 安装 FFmpeg；或关闭 `open_filter_resolution` |
| 生成的外链指向 `127.0.0.1` | 未设置公网地址 | 设 `PUBLIC_URL` 或 `public_url` |
| Docker 端口被占用 | 宿主机 80 已被占用 | `PORT=8088 docker compose up -d` |
| SQLite 报 `disk I/O error` | 网络盘/只读挂载不支持 WAL | 程序会自动降级为 DELETE journal；仍失败则换本地盘 |
| 子模块目录为空 | 未初始化 submodule | `git submodule update --init --depth 1 tools/iptv-api` |
| 测试因代理失败 | axios + msw 在代理下异常 | 剥离 `http_proxy` / `https_proxy` 后重跑 |
