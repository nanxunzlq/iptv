### 2. `PlaylistTester.test(input)`（[core/PlaylistTester.js L17-L67](../../tools/iptv-checker/src/core/PlaylistTester.js#L17-L67)）

**执行顺序：**

1. `commandExists('ffprobe')`，缺失直接抛 `Executable "ffprobe" not found...`。
2. 校验输入类型（`Object` / `Buffer` / `string`）。
3. `playlistParser.parse(input)`，失败时把异常转成 `Error`。
4. 调用 `config.setUp(playlist)`（CLI 用它初始化进度条总数）。
5. 遍历 `playlist.items`：
   - `isUri(url)` 为假 → `status = { ok:false, code:'INVALID_URI', message:'Invalid URI' }`；
   - URL 规范化后命中 `Cache` → `status = { ok:false, code:'DUPLICATE', message:'Duplicate' }`；
   - 否则加入队列并写入缓存。
6. 并发：`parallel === 1` 串行，否则 `eachLimit(queue, parallel, ...)`。
7. 就地写回 `item.status`，最终返回整个 `playlist`。

**注意**：`DUPLICATE` / `INVALID_URI` 的条目**仍会触发 `afterEach`**，因此会出现在 `failed.m3u` 中。

### 3. `StreamTester.test(input)`（[core/StreamTester.js L16-L45](../../tools/iptv-checker/src/core/StreamTester.js#L16-L45)）

- 输入可为字符串（仅 URL）或对象；字符串会被包装成 `{ url }`。
- 检查 ffprobe → `delay` 等待（`TESTING` 下跳过）→ `beforeEach`。
- **两段式**：
  ```js
  await this.streamLoader.load(item)      // HTTP 预检
  item.status = await this.ffprobe.check(item)  // 媒体校验
  ```
- `load` 抛出的 status 对象会被 `catch` 直接赋给 `item.status`。
- 无论成功失败都会执行 `afterEach`。

### 4. `StreamLoader.load(item)`（[core/StreamLoader.js L44-L141](../../tools/iptv-checker/src/core/StreamLoader.js#L44-L141)）

**关键行为：**

| 行为 | 实现 |
|---|---|
| 非 http(s) URL | 直接 `resolve()`（跳过 HTTP 检查） |
| 超时 | `axios` timeout + `CancelToken` 定时取消（双保险） |
| UA | `item.http['user-agent']`（格式合法时）> `config.userAgent` |
| Referer | `item.http.referrer` > `config.httpReferer` |
| 代理 | socks 系列 → `SocksProxyAgent`；其他 → axios `proxy` 配置 |
| 状态码 | `validateStatus: 200–399 或 405` 视为成功 |
| 响应体上限 | `maxContentLength = 100 KB`；超限 → `resolve()`（交给 ffprobe） |
| 重定向去重 | `responseUrl` 规范化后若已缓存 → `DUPLICATE` |
| 失败归一 | `HttpErrorParser` → `{ ok:false, code, message }` |

### 5. `FFprobe.check(item)`（[core/FFprobe.js L20-L74](../../tools/iptv-checker/src/core/FFprobe.js#L20-L74)）

```js
async check(item) → { ok: true, code: 'OK', metadata } | { ok: false, code, message }
```

判定顺序：

1. 构建命令并 `execAsync(command, { timeout })`。
2. `stdout` 非 JSON 或缺 `stderr` → `FFMPEG_UNDEFINED`。
3. 解析后 `metadata.streams.length === 0` → `FFMPEG_STREAMS_NOT_FOUND`。
4. 成功 → `{ ok:true, code:'OK', metadata }`；`metadata` 含 `streams`、`format`，并附加从 stderr 解析出的 `requests`。
5. `exec` 抛错 → `FFprobeErrorParser.parse(err.message, item)` 映射错误码。

**测试注入**：`TESTING` 环境下不执行真实命令，而是读取 [tests/__mocks__/ffprobe.js](../../tools/iptv-checker/tests/__mocks__/ffprobe.js) 中按 URL 索引的预置输出。

### 6. 命令构建 `FFprobeCommandBuilder.build(item)`

生成形如：

```bash
ffprobe -of json -v error -hide_banner -show_streams -show_format \
  -timeout "8000000" -headers "Referer: ..." -user_agent "..." -http_proxy "..." "URL"
```

> `timeout` 以**微秒**传给 ffprobe（`ms * 1000`）。

### 7. 输出解析 `FFprobeOutputParser.parse(stdout, stderr)`

- `JSON.parse(stdout)`；
- 从 stderr 按 `\r\n\n` 分块，提取 `Opening '...' for reading` 与 `request: ...`，得到 `requests: [{ method, url, headers }]`。

### 8. 错误映射

- [FFprobeErrorParser](../../tools/iptv-checker/src/core/FFprobeErrorParser.js#L1-L31)：`Protocol not found` → `FFMPEG_PROTOCOL_NOT_FOUND`，`Server returned 404 Not Found` → `HTTP_NOT_FOUND` 等，未知 → `FFMPEG_UNDEFINED`。
- [HttpErrorParser](../../tools/iptv-checker/src/core/HttpErrorParser.js#L41-L64)：`err.response.status` 查表；`timeout` → `HTTP_REQUEST_TIMEOUT`；`ENOTFOUND` → `HTTP_NOT_FOUND`；`EPROTO` → `HTTP_PROTOCOL_ERROR`；`HPE*` → `HTTP_PARSE_ERROR`。
- 全部码表见 [errors.js](../../tools/iptv-checker/src/errors.js#L5-L56)。

### 9. `Playlist.append(item)`（[core/Playlist.js L3-L22](../../tools/iptv-checker/src/core/Playlist.js#L3-L22)）

#### 3.1 `test_speed(data, ipv6=False, callback=None, on_task_complete=None, pause_wait=None, reporter=None)`

```python
async def test_speed(data, ipv6=False, callback=None, on_task_complete=None,
                     pause_wait=None, reporter=None)
```

- 创建 4 个信号量：HTTP、probe、截图、以及全局 `asyncio.timeout(speed_test_timeout)`。
- 使用 `create_speed_test_session(concurrency)` 建立 aiohttp 会话，启动 `worker()` 协程池消费共享迭代器。
- 每条结果：
  - `check_channel_need_frozen()` 决定 `mark_url_bad/good`；
  - `is_valid_speed_result()` 判有效；
  - 达到 `speed_test_target` 且非 full 模式 → 该频道停止继续测（`stopped_channels`）；
  - 写入 `speed_test.log/.jsonl`，有效结果额外写 `result.log/.jsonl`；
  - 回调 `on_task_complete(cate, name, merged, is_channel_last, is_last, is_valid)`。
- 暂停支持：worker 每取一条前 `await pause_wait()`。
- 取消语义：仅当**任务自身被取消**（`task.cancelling()`）才继续抛出；超时导致的 `CancelledError` 会转为失败结果。

#### 3.2 `sort_channel_result(channel_data, result=None, filter_host=False, ipv6_support=True, cate=None, name=None)`

- `unmatch` 分类：直接原序保留，不排序。
- 保留来源 `retain_origin`（`whitelist`、`hls`）置顶。
- `filter_host=True` 时，同 host 共用测速数据（`get_speed_result(host)`）。
- 排序由 `get_sort_result()` 按 `sort_by`（speed/delay/resolution）执行。
- 最终用 `stable_result_id(url, headers)` 去重。

#### 3.3 `write_channel_to_file(data, ipv6=False, first_channel_name=None, skip_print=False, is_last=False, reporter=None)`

写入 3 个基础文件：

| 文件 | 内容 |
|---|---|
| `config.final_file`（默认 `output/result.txt`） | 全量（按 `ipv_type_prefer`） |
| `output/ipv4/result.txt` | 仅 IPv4 |
| `output/ipv6/result.txt` | 仅 IPv6 |

当 `config.rtmp_available` 且**非 GitHub Actions** 时追加 3 个 HLS 文件（`hls.txt`、`ipv4/hls.txt`、`ipv6/hls.txt`），并同步 RTMP 快照表。

#### 3.4 `process_write_content(...)`

- 按分类输出 `分类,#genre#`，逐频道输出 `频道名,URL`。
- 应用 `_get_total_urls_cached()` 做来源/协议偏好与条数限制。
- `open_empty_category` 时追加"无结果频道"分类（仅最后一次写入）。
- 计算渲染签名，未变化则跳过；变化时临时文件 + `os.replace`，随后 `convert_to_m3u()` 生成同名 `.m3u`。

### 6. 可播性判定（[utils/channel_quality.py](../../tools/iptv-api/utils/channel_quality.py)）

```python
channel_result_rejection(item, *, retain_special=False, supply=None,
                         filter_speed=None, min_speed=None,
                         resolution_speed_map=None, filter_resolution=None,
                         min_resolution=None, max_resolution=None) -> str | None
```

返回拒绝原因（`unreachable` / `filtered_speed` / `filtered_resolution`）或 `None`（通过）。

判定顺序：

1. `retain_special` 且来源为 `whitelist/hls` → 直接通过；
2. `speed` 非正/非有限，或 `delay < 0` → `unreachable`；
3. `open_supply` → 通过（补充模式不卡质量）；
4. 速率低于 `resolution_speed_map[resolution]` 或 `min_speed` → `filtered_speed`；
5. 分辨率越界 → `filtered_resolution`。

### 8. 采集

#### 8.1 `get_channels_by_subscribe_urls(...)`（[updates/subscribe/request.py L65-L304](../../tools/iptv-api/updates/subscribe/request.py#L65)）

```python
async def get_channels_by_subscribe_urls(urls, names=None, whitelist=None,
                                         callback=None, epg_urls_out=None,
                                         pause_wait=None, reporter=None)
```

- `names` 先经 `format_channel_name()` 归一；
- 白名单 URL 优先排序；
- `asyncio.Semaphore(fetch_workers)` 控制并发；
- 解析支持 txt 与 m3u（`get_name_value`），保留 `$` 后的 `extra_info`、headers、catchup、tvg-logo；
- 未匹配频道写 `unmatch.log`；`open_auto_disable_source` 时将失败源在 `subscribe.txt` 前置 `#`；
- 返回 `{频道名: [ChannelData...]}`。

#### 8.2 `get_epg(names=None, callback=None, extra_entries=None, pause_wait=None, reporter=None)`（[updates/epg/request.py L388-L544](../../tools/iptv-api/updates/epg/request.py#L388)）

- 合并白名单、默认、订阅发现的 EPG 地址，去重并限流；
- `EpgStreamParser` 增量解析 XML，避免整份 DOM 占用内存；
- 用内容哈希跳过重复源；
- 同一频道同一时间段按 `_priority` 保留更高优先级节目；
- 返回 `{频道名: [programme...]}`，随后 `write_to_xml()` + `compress_to_gz()`。

### 9. Web 服务路由（[service/app.py](../../tools/iptv-api/service/app.py#L120-L294)）

### 10. 推流（[service/rtmp.py](../../tools/iptv-api/service/rtmp.py)）

### 12. GUI 协作要点

- 入口 [desktop_ui/app.py](../../tools/iptv-api/desktop_ui/app.py#L66-L115)：准备运行目录 → 单实例锁 → 字体/主题 → `MainWindow`。
- `--service` 模式：复制打包资源后调用 `run_service(parent_pid=...)`，由服务监控 GUI 进程存活。
- `controller.py` 负责把更新放到后台线程，通过信号把进度/事件送回页面；`pages/*` 只做展示与用户操作。
- `ChannelOperations`（[utils/channel_operations.py](../../tools/iptv-api/utils/channel_operations.py)）提供 GUI 的"重测单条/整频道/整分类、截图、重排发布"能力。
